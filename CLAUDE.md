# +Life — лендинг (контекст для Claude Code)

Статический русскоязычный лендинг HealthTech-продукта +Life — персональный ИИ-помощник по профилактике здоровья. Без билд-шага, без фреймворка: чистый HTML/CSS/vanilla JS.

## Структура файлов

- `index.html` — главная страница, все основные секции лендинга (nav, hero, статистика, проблема, решение, карта здоровья, ИИ-коуч, подготовка к врачу, превентивный план, каналы связи, доверие, персоны, онбординг, финальный CTA, футер).
- `styles.css` — единая таблица стилей для всех страниц. Все стили только здесь, инлайн-стили — исключение, не практика.
- `subpage.js` — общий JS для 4 персона-подстраниц (навигация, мобильное меню, dropdown функций, scroll-reveal).
- `segment-1.html` … `segment-4.html` — 4 подстраницы под персоны/сценарии («Не хочу пропустить важное», «У меня уже слишком много данных», «Хочу свою систему здоровья», «У меня уже есть своя система здоровья»). Ссылаются на `styles.css` + `subpage.js`, используют `index.html#...` для переходов к секциям главной.

Как смотреть локально: любой статический сервер, например `python3 -m http.server 8000`, затем открыть `http://localhost:8000/index.html`. Можно и просто открыть файл в браузере напрямую.

## Дизайн-система

- Стиль: «editorial + clinical + premium» — контраст тёмных/светлых секций (`.s-light` / `.s-dark` / `.s-dark2`), кремовый + графитовый + неоново-зелёный акцент `#39ff6e`.
- Шрифты: DM Mono / DM Sans / Playfair Display (Google Fonts, подключены в `<head>`).
- Скролл-анимации: класс `.sr` (+ модификаторы `.d1`…`.d4` — задержка, `.left`/`.right` — направление появления), запускаются через `IntersectionObserver` в конце `<script>` `index.html` и в `subpage.js`.
- Везде, где есть анимация (canvas-орбиты, scroll-reveal), учитывается `prefers-reduced-motion`.

## Контентные правила (важно соблюдать при любой правке текста)

Продукт медицинский/health — жёсткие ограничения на формулировки:

1. Никаких утверждений о диагнозе — +Life не ставит диагнозы.
2. Никаких гарантий результата.
3. Никаких точных «уровней здоровья/риска» в виде выдуманных precise-цифр — только честные качественные уровни уверенности (высокая/средняя) с пояснением «почему не выше».
4. «Doctor gate»: финальное клиническое решение всегда за врачом, ИИ передаёт решение врачу, а не принимает его сам.
5. Демо/синтетические данные обязательно помечены тегом «ПРИМЕР ДАННЫХ».
6. У значимых фактов должен быть указан источник (документ / дата / показатель / уровень уверенности) — паттерн provenance-UI (см. `.evidence-card` в `#trust`).
7. Язык — только русский, кроме «общепринятых» терминов: LDL, LDL-C, ApoB, PDF, названия отчётов ВОЗ/OECD. Всё остальное английское должно быть переведено (AI → ИИ, Health Coach → ИИ-коуч, baseline → базовые показатели и т.п.).
8. Дисклеймер «+Life не заменяет врача и не предназначен для самостоятельной постановки диагноза или назначения лечения» должен оставаться в ключевых CTA-секциях и футере.

## CTA-конфигурация (единая точка правки)

В конце `<script>` в `index.html`:

```js
var PRIMARY_CTA_URL = "#onboarding";   // «Начать» / «Собрать карту здоровья» / «Начать с моих данных»
var PRODUCT_DEMO_URL = "#coach";       // «Посмотреть продукт»
```

Все элементы с `data-cta="primary"` / `data-cta="demo"` получают `href` из этих переменных. Чтобы поменять реальный destination-URL кнопок — правится одно место.

## Canvas-визуализация «orbit»

Фабрика `initOrbit(canvas, fallback, labels, opts)` в конце `<script>` `index.html`:

- рисует вращающуюся 3D-подобную сферу узлов вокруг центра «+Life» (распределение точек по сфере — Fibonacci sphere, перспективная проекция, сортировка по глубине для правильного перекрытия);
- используется дважды: в hero (крупная, 9 узлов — устройства/документы) и в `#channels` (компактная, 5 узлов);
- ставится на паузу вне viewport и при `prefers-reduced-motion` (см. `IntersectionObserver` + `reducedMotion` в скрипте);
- список узлов и размер задаются параметрами в вызовах внизу файла — самих узлов и их положение вручную не редактируют.

## Навигация

- В шапке (`.nav`) — выпадашка «Функции продукта» (`<details class="nav-features">`) со списком якорей по всем функциональным секциям. При добавлении новой секции с якорем — добавить пункт в этот dropdown **во всех 5 HTML-файлах** (единого шаблона/include нет, шапка и футер продублированы вручную в `index.html` и каждом `segment-N.html`).
- Мобильное меню использует атрибут `inert` для скрытых вне экрана ссылок (см. `syncNavInert()`).

## История разработки (кратко)

1. Первая версия построена по исходному ТЗ v1.1 + adversarial review prompt (15 секций, медицинские safety-правила).
2. Adversarial compliance review — найден и закрыт BLOCKER: ссылка «Безопасность» в nav/футере вела в секцию `#trust` без контента про данные пользователя → добавлен принцип «Ваши данные».
3. Большой раунд правок по фидбеку:
   - «Документы» → «Медзаключения» в orbit-визуализации;
   - `#segments` переделан из явных «сегментов» в 4 персона-карточки, добавлен 4-й сценарий («уже есть своя система здоровья»), созданы подстраницы `segment-1..4.html`;
   - полный перевод английских терминов на русский (кроме LDL/ApoB/PDF/WHO-OECD);
   - `#evidence` (статистика проблем) перенесена сразу после hero, к каждой цифре добавлено «потенциально помогает: …»;
   - hero-блок с демо-карточкой конкретного пользователя заменён на текст про комплексного превентивного ИИ-помощника + orbit-визуализация с +Life в центре.
4. Второй раунд:
   - добавлен заголовок к статистике, убран дисклеймер под ней;
   - orbit увеличена, поднята выше, добавлены новые типы устройств (браслет, тонометр, глюкометр и т.д.);
   - убран picker «Похоже на вас?» под hero;
   - портреты персон сделаны более «антропоморфными»;
   - в шапку добавлена выпадашка «Функции продукта».
5. Третий раунд:
   - иконки персон заменены на AI-сгенерированные фотопортреты (сейчас — внешние ссылки на `cdn.gamma.app`, с graceful fallback через класс `.img-error` при ошибке загрузки изображения);
   - orbit-визуализация переделана в честный 3D-рендер (Fibonacci sphere + перспектива + depth sorting), плоские orbit-кольца убраны, внешняя граница стала «стеклянной сферой».

## Известные открытые вопросы

- 4 фото персон в `#segments` — внешние ссылки на `cdn.gamma.app`, содержимое визуально не проверялось из среды разработки (сетевые ограничения). Стоит открыть страницу и посмотреть, устраивают ли фото по стилю/качеству. Если нет — можно перегенерировать или вернуть предыдущие стилизованные SVG-фигуры (есть в git-истории репозитория).
- Все данные в демо-карточках (LDL-C, карта здоровья, экспорт для врача и т.д.) — синтетические примеры, помечены «ПРИМЕР ДАННЫХ» согласно контентным правилам.
- CTA-кнопки сейчас ведут на локальные якоря (`#onboarding`, `#coach`) — реальный destination-URL ещё не определён, это осознанное временное решение с единой точкой конфигурации (см. раздел «CTA-конфигурация» выше) для лёгкой замены в будущем.
